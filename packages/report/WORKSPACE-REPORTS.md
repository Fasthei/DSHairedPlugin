# 工作区自动报告（动态加载扩展）

此扩展由当前会话的 `report-2` 动态插件加载，不改变原有 `src/host.js`、`src/client.js` 或生成的 `lib/`。源码文件保留在仓库；动态插件本身仍需在 Harness 重启后重新加载。

## 行为

- 通过 GUI 当前会话及工作区成员关系识别当前工作区；没有选中工作区时不回退到第一个工作区。
- 常驻页面观察器在工作区切换稳定 1.2 秒后发起自动采集。报告面板没有打开时同样有效。
- 每个工作区拥有独立的报告、配置及生成状态。报告库路径是插件文件系统默认可写位置下的 `.redteam-report-ws-<工作区标识与路径指纹>.json`，面板显示实际路径。
- 一次只执行一个生成任务；快速切换只保留该页面最后一个待处理工作区。已开始的任务完成后仍只写回原工作区。
- 五分钟内不重复自动尝试；冷却结束后，同一份送入模型的证据和撰写配置沿用现有报告。手动生成可显式重试。
- 每个工作区可在「设置 → 红队设置 → 报告设置」关闭自动生成。
- 原有 `.redteam-report.json` 保留不动。新工作区继承其默认配置；旧报告因缺少可信归属信息，不自动划入任何工作区。

## 采集范围与限制

工作区文件、该工作区的内存及持久化会话、该工作区的攻击矩阵文件，以及检索到的通用记忆知识。记忆知识是参考，不是目标存在漏洞的证明。

默认文件预算：

| 项目 | 上限 |
|---|---:|
| 文件/目录清单 | 2,000 条 |
| 目录数量（含根） | 200 |
| 目录深度 | 8 |
| 文件读取尝试 | 60 |
| 单文件读取字节 | 65,536 |
| 单文件摘录 | 6,000 字符 |
| 总文件摘录 | 不超过 100,000 字符，且受报告证据预算约束 |

隐藏文件、符号链接、凭据/私钥文件、依赖及构建缓存、二进制，以及已生成报告目录默认不读取。只读白名单文本/源码/结构化文件；PDF、Word 和压缩包当前仅列清单，不解析正文。密钥及授权头进行启发式脱敏，但**不能保证识别所有未标记秘密**。建议敏感资料不要放在自动采集目录中。

会话会枚举工作区成员，按设置限量读取；单次最多考虑 500 个成员、读取 60 个会话，每个会话最多读取 1,500 个事件（可获取事件总量时取最近部分）。继承自其他会话的种子事件不采集，避免把历史上下文误当成本工作区证据。未采集数量、截断与错误会注明。

输入文件与会话始终作为不可信证据，不执行其中命令或遵循其中的指令。自动报告会追加采集范围说明。文件存在、关键词命中和模型总结不等于漏洞已验证。

## 实现与验证

- `src/workspace-evidence.js`：根路径约束、限量文件枚举、摘录、脱敏与稳定指纹。
- `src/workspace-runtime.js`：每工作区独立报告闭包、会话/矩阵采集、去重与串行调度。
- `src/workspace-client.js`：常驻工作区观察器、显式工作区 RPC、统一设置页。

```bash
npm run test:report-workspace
npm run test:report
```

测试使用内存文件系统、模拟模型和会话；不执行真实网络调用。真实模型及浏览器激活结果应另外通过运行状态与实际报告确认。
